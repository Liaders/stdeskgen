# Окно конструктора и публикации

Запустите **start-desktop.cmd** двойным щелчком. Он вызывает PS1-скрипт
`start-desktop.ps1`. Установка самой оболочки не требуется: нужны Windows x64,
Windows PowerShell, Python из проекта, Microsoft Edge WebView2 Runtime и Git.
SDK WebView2 скачивается с официального NuGet при первом запуске; проверяется
его закреплённый SHA-512. SDK и профиль браузера не попадают в Git.

## Конструктор

Первая вкладка открывает http://127.0.0.1:8765/ внутри окна через WebView2.
Локальный сервер запускается автоматически. Если порт занят прежним
конструктором без новых функций, закройте его CMD и повторите запуск.
Два одновременно запущенных экземпляра оболочки не рекомендуются.

Список последних сборок обновляется каждые несколько секунд. Фоновый процесс
проверяет GitHub, сначала обновляет статусы всех известных запусков, затем
скачивает установщики успешных сборок. Время скачивания не означает, что
компиляция всё ещё стоит в очереди. Если запуск не найден, это указано отдельно.

Файлы сохраняются в **rdgen/downloads/<идентификатор сборки>/**. Архивы
проверяются на выход за каталог; извлекаются установщики и данные сборки,
а не исполняемые скрипты. В каталоге хранятся источник run, платформа, версия,
размер и SHA-256. Повторное открытие окна не скачивает готовые файлы повторно.
Для ошибки загрузки предусмотрена кнопка повторного скачивания.

Проверка/скачивание работают, пока запущен локальный конструктор. После
закрытия оболочки её собственный сервер останавливается; следующий запуск
возобновит незавершённое скачивание. Сама сборка GitHub продолжает работать.
Если сервер был запущен отдельно, оболочка не останавливает его при закрытии.

Для новой Windows-сборки нажмите **«Настроить автообновление Windows для
новой сборки»**. Настроятся адрес desk.status16.ru/client, продукт statusdesk,
канал stable и новая возрастающая ревизия. Для следующей сборки нажмите
снова. Сохранённая конфигурация сохраняет прежнюю ревизию, пока вы её не
обновите — случайно перепубликовать её как новый выпуск сервер не позволит.

## Публикация

Выберите локальный установщик во второй вкладке. Список поддерживает фильтр
платформ и показывает версию/размер/исходную сборку. EXE проверяется по PE-заголовку:
Windows x64 и x86 не выбираются по имени файла или разрядности компьютера оператора.
Для Linux/macOS учитываются имя артефакта и архитектура в имени пакета из CI.
Если вы импортируете свой DMG/пакет, укажите правильную архитектуру вручную.

Кнопка **«Опубликовать»** использует локальную `.local-publish.json`, PuTTY
и уже настроенный локальный PPK-ключ. Ключ не копируется на сервер и не
отправляется в GitHub. Видны ход передачи, результат и технический журнал.
Можно открыть папку установщиков или публичную страницу скачивания.
Файл, отсутствующий в каталоге, можно добавить через форму внизу вкладки.

### Один файл для страницы и обновления

У Windows EXE с `stdesk-update-build.json` можно включить **«Этот же файл —
для автообновления»**. Используются скомпилированные платформа, имя приложения,
канал, продукт, версия и ревизия из receipt. При этом версия вручную не меняется.
Публикация формирует одновременно описание обновления и запись downloads.json.
Обе ссылки ведут на **один и тот же** неизменяемый EXE на сервере.

Windows x64 и x86 имеют отдельные описания:

```
/client/channels/statusdesk/stable/windows-x64.json
/client/channels/statusdesk/stable/windows-x86.json
```

Файлы выпуска находятся в /client/releases/<product>/<channel>/<platform>/<revision>/.
Архитектура зафиксирована в клиенте при компиляции. Клиент сверяет платформу,
имя приложения, ревизию, размер и SHA-256 и запускает существующую установку
RustDesk только без активных сеансов. Собственных ключей подписи нет.

**Старый клиент без поддержки этого канала нужно один раз обновить вручную.**
Одной публикацией файла добавить в уже установленный EXE этот код невозможно.
При настройке канала allow-auto-update включается по умолчанию. Явное отключение
в профиле или стратегии CortenDesk сохраняет приоритет.

Обычный импортированный файл без receipt публикуется для ручного скачивания.
Linux/macOS сейчас также публикуются для ручной установки: механизм фоновой
установки обновлений для этих ОС ещё не подключён. MSI/portable-обновления
не поддерживаются. До массового включения автообновлений нужна проверка двух
новых ревизий в Windows VM, включая сохранение настроек и перезапуск сервиса.

## Поверхность изменений

Существующие генерация конфигурации и отправка сборок сохранены. Новые поля
метаданных и фоновая проверка находятся рядом с local_build, скачивание и
desktop API вынесены в отдельные модули. Шаблоны показывают живые статусы.
Включённый update-адаптер получил выбор Windows x86/x64; выключенный не меняет
исходники RustDesk. Сервер публикации разделяет платформы и сохраняет один URL
для публичной загрузки и автоматического обновления. Архивы и SSH-настройки
остаются локальными и исключены из Git. Конфигурация Apache не переписывается.
