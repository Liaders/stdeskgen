# Локальный конструктор

## Запуск
Дважды щёлкните `start-local.cmd`, затем откройте http://127.0.0.1:8765. Окно запуска нужно оставить открытым. Нужны Python и Git Credential Manager с выполненным входом в GitHub. Если Git отсутствует в PATH, launcher также ищет Git из среды Codex.

По умолчанию используется Liaders/stdeskgen, ветка master. Переопределение: GHUSER, REPONAME, GHBRANCH. Пароль или GitHub token в форму вводить не нужно: авторизация читается из системного Git Credential Manager. Если регистрация аккаунта изменилась, выполните вход заново.

## Схема работы
1. Форма и обработчик работают только на 127.0.0.1. Публичный адрес, проброс портов, VPS и входящие соединения из GitHub не нужны.
2. Конструктор сохраняет конфигурацию и PNG в AES-зашифрованном ZIP. В публичный fork отправляется только этот архив в отдельной временной ветке. Отдельный случайный пароль каждой сборки хранится в GitHub Secret, загруженном через шифрование GitHub public key.
3. Workflow получает архив средствами GitHub, читает Secret и собирает клиент. Результат публикуется в Artifacts → client-windows-x64.
4. Локальная страница показывает статус и ссылку на GitHub. Сборка продолжится, если конструктор закрыть. Очистка временной ветки и Secret выполняется при проверке завершённой сборки, поэтому страницу статуса следует оставить открытой до завершения либо открыть её снова.

Конфигурация может содержать постоянный пароль, который затем входит в готовый клиент согласно исходному поведению rdgen. Скачиваемые артефакты публичного репозитория следует считать доступными пользователям GitHub. GitHub Secret защищает передачу конфигурации, но не делает содержимое готового клиентского приложения секретным.

Пока подключена Windows x64 / RustDesk 1.5.0. Для остальных платформ локальный запуск явно отклоняется; следующие этапы — Windows x86, Linux и macOS. Старые серверные workflows сохранены для совместимости, локальный режим их обратные вызовы не использует.
