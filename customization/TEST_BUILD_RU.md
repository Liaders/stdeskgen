# Тестовая сборка Windows x64

Workflow: `.github/workflows/test-ui-windows.yml` → **Test customized client — Windows x64**.

1. После загрузки изменений в GitHub открыть вкладку Actions и при необходимости включить workflows fork.
2. Выбрать workflow и нажать Run workflow. Для ручного запуска через интерфейс workflow должен находиться в основной ветке.
3. После успешной сборки скачать `stdesk-test-windows-x64` (самораспаковывающийся EXE) либо `stdesk-test-windows-x64-folder` (распаковать весь архив и запустить rustdesk.exe).

Сервер rdgen, GENURL, ZIP_PASSWORD, домен и сертификат подписи для этого workflow не нужны. Профиль берётся из `customization/example.json`. Сборка не подписана; оконный помощник режима приватности пока не включён. Это первая проверка интерфейса, не полная проверка всех функций клиента.

Исходники клиента закреплены на RustDesk 1.5.0 commit fada664df7a294d1d1a9ca3e7cd3637069122f17. Bridge собирается существующим reusable workflow по тегу 1.5.0. Инструменты и native build steps взяты из workflow этих исходников. Некоторые внешние зависимости upstream загружаются по изменяемым ссылкам; полностью воспроизводимая сборка требует их дополнительного закрепления.

Проверить вручную:
- светлую/тёмную темы, цвета кнопок и активных элементов;
- текстовую навигацию, узкое окно и масштаб Windows;
- ширину панелей и длинные имена;
- во вкладке доступных устройств: имя устройства до заполнения поля, псевдоним после заполнения, исходное имя после очистки;
- отмену диалога, поиск по псевдониму, перезапуск и сохранение значения;
- неизменность исходного hostname/ID и адресной книги.

Псевдонимы доступны во вкладке MyGroup и требуют доступных устройств от API после входа. Отсутствие этой вкладки/данных без API не означает, что тест хранения псевдонимов пройден.

План следующих целей: Windows x86, Linux x64, macOS Intel и Apple Silicon. Их сборки пока не подключены и не проверены; архитектуры Linux/macOS требуется подтвердить.
